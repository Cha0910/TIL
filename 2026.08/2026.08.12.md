## 2. 프로그래머스 문제 풀이

### [평행](https://school.programmers.co.kr/learn/courses/30/lessons/120875)

```cpp
#include <string>
#include <vector>

using namespace std;

int solution(vector<vector<int>> dots) {
    vector<vector<int>> candidates = 
    {
        {0, 1, 2, 3},
        {0, 2, 1, 3},
        {0, 3, 1, 2}
    };
    
    for(int i=0; i<candidates.size(); i++){
        int dx1 = dots[candidates[i][0]][0] - dots[candidates[i][1]][0];
        int dx2 = dots[candidates[i][2]][0] - dots[candidates[i][3]][0];
        int dy1 = dots[candidates[i][0]][1] - dots[candidates[i][1]][1];
        int dy2 = dots[candidates[i][2]][1] - dots[candidates[i][3]][1];
        if(dx1 * dy2 - dy1 * dx2 == 0) return 1;
    }
    
    return 0;
}
```

* **수학**, **구현** 문제
* 점 `4`개 중 **평행할 가능성이 있는 선분 조합**을 뽑는 경우의 수는 단 `3`개
* 평행한 선분은 **외적 값**이 `0`이므로 외적 값으로 판단

## 3. UDP 홀펀칭 (UDP Hole Punching)

### NAT (Network Address Translation)

* **사설 IP(Private IP)** 주소를 **공인 IP(Public IP)** 주소로 **변환**하는 기술

* NAT 장비(공유기 등)는 패킷의 발신지 사설 IP와 포트를 자신의 공인 IP와 임의의 포트로 변경해 통신

* NAT는 내부 주소와 외부 매핑 주소 간의 연관 관계를 **세션 테이블**에 기록해, 응답 패킷을 올바른 사설 기기로 전달

* **NAT**를 이용하는 이유는 대개 **사설 네트워크(Private Network)에 속한 여러 개의 호스트**가 **하나의 공인 IP 주소를 사용**하여 인터넷에 접속하기 위함

### P2P (Peer to Peer)

* 중앙 서버의 데이터 중계 없이 **클라이언트(Peer) 간에 직접 데이터를 주고받는 네트워크 방식**

* 서버의 트래픽, 대역폭을 절감해 **실시간 통신 지연 시간(Latency)을 최소화**

* 위의 NAT로 인해 **직접 접속이 차단**되어 P2P 통신이 불가능해짐

### UDP 홀펀칭 (UDP Hole Punching)

* NAT 뒤에 위치한 두 P2P 클라이언트가 **서로 직접 통신할 수 있도록 NAT 세션 테이블에 경로(구멍)를 뚫는 Traversal 기술**

* **중계 서버(STUN/Signal Server)** 를 거쳐 양쪽 클라이언트의 **공인 IP 및 매핑 포트 정보를 사전에 서로 교환**

* 서로의 공인 주소로 UDP 패킷을 발송하여, 각자의 NAT 장비에 **상대방 전용 인바운드 허용 세션을 생성**

* 이후 양 클라이언트가 교환한 **상대방의 공인 주소**로 P2P 통신 수행

* UDP의 특성상 **일정 시간 통신이 없을 경우 NAT 세션이 삭제**되므로 일정 주기마다 **Ping**을 보냄
